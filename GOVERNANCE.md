# Governance

Codex Remote currently uses a maintainer-led governance model.

Maintainers own repository permissions, roadmap decisions, security response,
release approval, and final merge decisions. Contributors influence the
project through issues, design proposals, reviews, and pull requests.

Routine changes are decided in the owning repository. Changes to public
protocols, authentication, security boundaries, repository ownership, or
cross-repository compatibility require a written issue or ADR and explicit
maintainer approval before implementation is merged.

Maintainer status is granted based on sustained, trusted contributions,
technical judgment, respectful collaboration, and demonstrated care for the
project's security and compatibility boundaries. It may be removed after
prolonged inactivity or violations of project policy.
